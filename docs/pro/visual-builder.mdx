# Visual Builder

**WP Admin → CtrlField → Visual Builder** sets up a new content model in four steps:

1. **Content**: the post type, with plural and singular names, a key made from the singular name, an icon, whether it is public, and an archive page.
2. **Taxonomies**: new ones for this content, either like categories or like tags, and existing ones to use with it (Categories, Tags…).
3. **Fields**: an empty field group shown on the new post type.
4. **Review**: everything that will be created.

Nothing is saved until **Create content model**, and then everything is saved together. Keys are checked while you type and again on the server: WordPress's reserved names (`post`, `year`, `name`…) and keys already in use are refused. The field group then opens in the **Field Groups** editor, ready for its fields.

Each part can be changed later on its own:

- **CtrlField → Post Types**: post types and, in the *Taxonomies* tab, taxonomies. URLs, archive, REST base, search, permissions, linked taxonomies; **Export PHP** for each.
- **CtrlField → Field Groups**: the fields. **Export PHP** shows the group as code; **Save as PHP file** writes it into your schema folder (`CTRLFIELD_SCHEMA_PATH`), where code takes precedence over the admin copy.

---

## From the admin to code

Everything made here can move to version-controlled PHP:

```php
CPT::make('team_member')
    ->label('Team member', 'Team members')
    ->menuIcon('dashicons-groups')
    ->supports(['title', 'editor', 'thumbnail'])
    ->hasArchive(true)
    ->taxonomies(['category'])
    ->register();

Taxonomy::make('department')
    ->label('Department', 'Departments')
    ->attachTo(['team_member'])
    ->hierarchical(true)
    ->register();
```

Once the files are in your schema folder, delete the admin copies: post types, taxonomies and field groups defined in code take precedence, and the stored entries, terms and values stay as they are.
