# ComponentRegistry

Auto-discovers and registers page components from a directory. This is the foundation of CtrlField's page-builder system.

---

## Setup

```php
// functions.php
add_action('init', function () {
    \CtrlField\Components\ComponentRegistry::discover(
        get_template_directory() . '/components/'
    );
}, 5);
```

---

## Discovery options

A theme whose components already follow their own conventions passes them as
the third argument, instead of writing its own registry:

```php
use CtrlField\Components\ComponentDefinition;
use CtrlField\Components\ComponentRegistry;

ComponentRegistry::discover(get_template_directory() . '/components', 'fields.php', [
    // Layout key from the folder name: 'lower' (default, ModuleTabs → moduletabs),
    // 'snake' (module_tabs), 'kebab' (module-tabs) or fn (string $folder): string.
    'key'          => 'snake',

    // Template names, in order. {folder} and {key} are replaced.
    // Default: index.blade.php → index.twig → index.php
    'templates'    => ['{folder}.blade.php', 'index.blade.php'],

    // Top-level field keys get "{key}_" (title → module_tabs_title), so data
    // saved with prefixed keys (e.g. migrated from Carbon Fields) stays readable.
    // Conditions on sibling fields (visibleWhen('layout', …)) follow the new keys.
    'prefixFields' => true,

    // Folders that are no page component.
    'skip'         => ['ModuleNavigation', 'ModuleFooter'],

    // Loads fields.php in the theme's context (helpers that build prefixed keys
    // for conditions, shared fields…). Each file is loaded once per request;
    // ->autoDiscover() reuses the result. A file that throws is skipped and
    // shown to admins in a notice.
    'load'         => fn (string $file, string $key, string $folder) => ComponentFields::forComponent($key, fn () => require $file),

    // The theme loads each component's script.js itself: the plugin's
    // component loader stays off (also: add_filter('ctrlfield/component_scripts', '__return_empty_array')).
    'scripts'      => false,

    // What fields.php returned → the layout's fields (add shared fields, …).
    'fields'       => fn (array $fields, ComponentDefinition $c): array => [...$fields, ...sharedFields($c->key)],

    // Label / category / description / icon from the theme's own metadata
    // (e.g. static properties of the component class). Wins over fields.php.
    'meta'         => function (string $folder, string $path): array {
        $class = "\\Components\\{$folder}";
        return class_exists($class)
            ? ['label' => $class::$label ?? '', 'category' => $class::$category ?? '']
            : [];
    },

    // Prepares a section before its template renders (the theme's getData()).
    // Runs before the ctrlfield/component_data filters.
    'data'         => function (array $section, ComponentDefinition $c): array {
        $class = "\\Components\\{$c->folder}";
        return $class::getData($section);
    },
]);
```

`->autoDiscover()` on a flexible content field builds its layouts with the same
options, so the page builder, the saved data and the renderer all use one key.

The list of component folders is cached (until the folder or one of the
components changes; not while `WP_DEBUG` is on). The fields files themselves
are loaded on each request, like any schema.

## Component directory structure

A component is any subdirectory that contains a `fields.php` file:

```
components/
├── hero/
│   ├── fields.php          ← REQUIRED — returns FlexLayout
│   ├── index.blade.php     ← optional — Blade template
│   ├── index.twig          ← optional — Twig template
│   ├── index.php           ← optional — PHP template
│   ├── functions.php       ← optional — auto-loaded, register filters
│   ├── script.js           ← optional — lazy-loaded JS
│   └── screenshot.png      ← optional — shown in the picker modal
├── features/
│   └── fields.php
└── cta/
    └── fields.php
```

## `fields.php` contract

Each component's `fields.php` must return a `FlexLayout` instance:

```php
// components/hero/fields.php
use CtrlField\Pro\Fields\FlexLayout;
use CtrlField\Fields\Field;
use CtrlField\Fields\FieldPresets;

return FlexLayout::make('hero')
    ->label('Hero Banner')
    ->icon('cover-image')
    ->category('layout')
    ->description('Full-width hero with headline, subtext and CTA.')
    ->fields([
        Field::text('headline')->label('Headline')->required(),
        Field::textarea('subtext')->label('Subtext'),
        Field::image('background')->returnFormat('array'),
        Field::link('cta')->label('CTA Button'),
        FieldPresets::theme(),
    ]);
```

Alternatively, return an array of `FieldDefinition` instances. The layout key and label are derived from the directory name:

```php
// components/simple/fields.php
return [
    Field::text('title')->label('Title'),
    Field::textarea('body')->label('Body'),
];
```

## `functions.php` — component data transforms

`functions.php` is auto-loaded immediately after the component is registered. Use it to register data filters:

```php
// components/hero/functions.php
add_filter('ctrlfield/component_data/hero', function (array $data): array {
    // Merge in computed or global values
    $data['site_name'] = get_bloginfo('name');
    return $data;
});
```

## API

```php
ComponentRegistry::discover(string $basePath, string $fieldsFile = 'fields.php'): void

ComponentRegistry::all(): array<string, ComponentDefinition>
ComponentRegistry::getPath(string $key): ?string
ComponentRegistry::getTemplatePath(string $key): ?string
ComponentRegistry::reset(): void  // tests only
```

## Checks

**CtrlField → Schema Inspector → Components** and `wp ctrlfield components validate` report, for each component, a fields file that does not load, a missing template and the schema problems inside its layout. A theme adds the checks of its own conventions with `ctrlfield/component_issues`:

```php
add_filter('ctrlfield/component_issues', function (array $issues, \CtrlField\Components\ComponentDefinition $component): array {
    if (! is_file($component->path . '/' . $component->folder . '.php')) {
        $issues[] = ['level' => 'error', 'message' => 'No component class.'];
    }
    return $issues;
}, 10, 2);
```

Each issue is `['level' => 'error' | 'warning', 'message' => string]`. Errors make `validate` fail; warnings fail only with `--strict`.

## Template priority

| Priority | Extension | Engine |
|---|---|---|
| 1st | `index.blade.php` | Blade |
| 2nd | `index.twig` | Twig via Timber |
| 3rd | `index.php` | PHP with extract() |

## Rendering in templates

```blade
@foreach(ctrlfield_get('page_builder') as $section)
    @ctrlfSection($section)
@endforeach
```

```twig
{% for section in ctrlfield_get('page_builder') %}
    {{ ctrlf_component(section)|raw }}
{% endfor %}
```

```php
foreach (ctrlfield_get('page_builder') as $section) {
    ctrlfield_render_component($section);
}
```
